# DQN Training and Mixing Estimation Experiments

This repository contains experiments for training DQN agents and estimating dependence in replay-buffer minibatches and policy trajectories.

The main workflows are:

1. Train a DQN agent.
2. Optionally log sampled minibatches during training.
3. Estimate tau-mixing coefficients for logged minibatches.
4. Estimate tau-mixing coefficients for trajectories generated by a trained policy.
5. Plot the estimated mixing coefficients.

Training and dependence-estimation experiments use [Hydra](https://hydra.cc/) for configuration. The plotting utility currently uses a small `argparse` interface.

The recommended way to run the experiments is from the project root using Python module execution:

```bash
python -m experiments.train_agent
python -m experiments.estimate_minibatch_mixing
python -m experiments.estimate_trajectory_dependence
python -m experiments.plot_tau_estimates
```

## 1. Training a DQN Agent

The training entry point is:

```text
experiments/train_agent.py
```

The training script uses the Hydra config:

```text
experiments/conf/train/config.yaml
```

The Hydra decorator in `train_agent.py` should point to the training config directory:

```python
@hydra.main(version_base=None, config_path="conf/train", config_name="config")
def main(cfg):
    ...
```

This allows the script to be run from the project root with:

```bash
python -m experiments.train_agent
```

---

### Training Base Config

The base training config is:

```text
experiments/conf/train/config.yaml
```

Example:

```yaml
defaults:
  - _self_
  - dqn: cartpole
  - sampler: yu_contiguous_block

seed: 0

buffer_path: null
render: false
save_model_path: null
load_model_path: null
minibatch_log_path: null
sample_with_replacement: true

hydra:
  job:
    chdir: false
```

The default training run uses:

- `CartPole-v1`
- CartPole DQN hyperparameters
- `YuContiguousBlockSampler`
- seed `null` (this means no seed is used)
- no model checkpoint loading
- no model checkpoint saving
- no rendering
- no minibatch logging unless `minibatch_log_path` is provided
 
Note: `None` in Python corresponds to `null` in yaml.

---

### DQN Hyperparameter Configs

DQN hyperparameter configs are stored in:

```text
experiments/conf/train/dqn/
```

For example:

```text
experiments/conf/train/dqn/cartpole.yaml
```

```yaml
# @package _global_

env_name: CartPole-v1

dqn:
  discount: 0.99
  buffer_size: 100000
  max_episodes: 1000
  minibatch_size: 128
  eps_schedule: 0.99
  exploration_fraction: 0.2
  lr: 0.001
  tau: 1.0
  eps_min: 0.05
  t_target: 10
  start_time: 1000
  update_freq: 256
  n_updates: 128
  q_net_kwargs:
    hidden_layers: [256, 256]
```

Each DQN config sets both:

```yaml
env_name: ...
```

and:

```yaml
dqn:
  ...
```

Therefore, selecting a DQN config also selects the corresponding Gymnasium environment.

Available DQN configs include:

```text
cartpole
lunarlander
cliffwalking
frozenlake
pong
```

### Sampler Configs

Replay-buffer sampler configs are stored in:

```text
experiments/conf/train/sampler/
```

The selected sampler is instantiated using Hydra and passed to the DQN agent.

#### Uniform Sampler

```text
experiments/conf/train/sampler/uniform.yaml
```

```yaml
# @package sampler

_target_: src.buffers.samplers.UniformSampler
replace: ${sample_with_replacement}
rng:
  _target_: numpy.random.default_rng
  seed: ${seed}
```

#### Ordered Uniform Sampler

```text
experiments/conf/train/sampler/ordered_uniform.yaml
```

```yaml
# @package sampler

_target_: src.buffers.samplers.OrderedUniformSampler
replace: ${sample_with_replacement}
rng:
  _target_: numpy.random.default_rng
  seed: ${seed}
```

#### Yu Contiguous Block Sampler

```text
experiments/conf/train/sampler/yu_contiguous_block.yaml
```

```yaml
# @package sampler

_target_: src.buffers.samplers.YuContiguousBlockSampler
block_length: 48
gap_length: 2
seed: ${seed}
sort: true
wraparound: true
```

#### No Custom Sampler

```text
experiments/conf/train/sampler/none.yaml
```

```yaml
# @package _global_

sampler: null
```

This passes `sampler=None` to the DQN agent, in which case it will revert to default uniform sampling.


Example:

```bash
python -m experiments.estimate_minibatch_mixing \
```

```bash
python -m experiments.estimate_minibatch_mixing \
```

Override the number of nearest neighbours:

```bash
python -m experiments.estimate_minibatch_mixing \
  minibatch_file=logs/minibatches/cartpole.npz \
  output=results/minibatch_tau/cartpole.npy \
  knn=40
```

Run using 8 CPU cores:

```bash
python -m experiments.estimate_minibatch_mixing \
  minibatch_file=logs/minibatches/cartpole.npz \
  output=results/minibatch_tau/cartpole.npy \
  num_cores=8
```

Use all available cores:

```bash
python -m experiments.estimate_minibatch_mixing \
  minibatch_file=logs/minibatches/cartpole.npz \
  output=results/minibatch_tau/cartpole.npy \
  num_cores=-1
```

---

### Expected Input and Output

The input file should contain logged minibatches. The expected minibatch array shape is:

```text
(n_minibatches, batch_size, dimension)
```

If the loaded minibatch array has a singleton first dimension, for example:

```text
(1, n_minibatches, batch_size, dimension)
```

the script squeezes that first dimension.

The output is saved as a NumPy `.npy` file. The expected output shape is:

```text
(n_minibatches, max_lag)
```

Each row corresponds to one minibatch, and each column corresponds to a lag value.

## 4. Plotting Estimated Mixing Coefficients

The plotting entry point is:

```text
experiments/plot_tau_estimates.py
```

This script loads a saved NumPy array of estimated tau-mixing coefficients and plots the mean estimate across runs, minibatches, or trajectories.

The plotting utility currently uses `argparse` rather than Hydra.

---

### Expected Input

The plotting script expects a NumPy `.npy` file containing tau estimates.

The input file should usually be one of the outputs produced by:

```text
experiments/estimate_minibatch_mixing.py
experiments/estimate_trajectory_dependence.py
```

The expected input shape is either:

```text
(max_lag,)
```

or:

```text
(n_estimates, max_lag)
```

For minibatch mixing estimation, the input is usually:

```text
(n_minibatches, max_lag)
```

For trajectory dependence estimation, the input is usually:

```text
(n_rollouts, max_lag)
```

If a one-dimensional array is provided, the plotting script treats it as a single estimate.

---

### What the Plot Shows

The plot shows:

- the mean estimated tau-mixing coefficient at each lag,
- an uncertainty band corresponding to approximately `±2` standard errors,
- the lag index on the horizontal axis,
- the estimated tau-mixing coefficient on the vertical axis.

The plotted quantity is labelled as:

```latex
\hat{\tau}^m_X(k)
```

where `k` is the lag.

---

### Basic Plotting Usage

Plot estimates without saving the figure:

```bash
python -m experiments.plot_tau_estimates \
  --tau_estimates_path results/minibatch_tau/cartpole.npy
```

Plot trajectory-dependence estimates without saving the figure:

```bash
python -m experiments.plot_tau_estimates \
  --tau_estimates_path results/trajectory_tau/cartpole.npy
```

---

### Saving the Plot

Save the plot to a file using `--save_path`:

```bash
python -m experiments.plot_tau_estimates \
  --tau_estimates_path results/minibatch_tau/cartpole.npy \
  --save_path figures/minibatch_tau_cartpole.pdf
```

or:

```bash
python -m experiments.plot_tau_estimates \
  --tau_estimates_path results/trajectory_tau/cartpole.npy \
  --save_path figures/trajectory_tau_cartpole.pdf
```

The script saves the figure with:

```python
dpi=1200
bbox_inches="tight"
```

This is suitable for high-resolution paper figures.

Make sure the output directory exists before saving:

```bash
mkdir -p figures
```

---

### LaTeX Rendering

The plotting script uses:

```python
mpl.rcParams["text.usetex"] = True
```

This requires a working LaTeX installation.

If you do not have LaTeX installed, either install a LaTeX distribution or change the line to:

```python
mpl.rcParams["text.usetex"] = False
```

Without a LaTeX installation, Matplotlib may raise an error when rendering or saving the plot.

## 6. Notes on Paths

All Hydra configs use:

```yaml
hydra:
  job:
    chdir: false
```

This means relative paths are resolved from the directory where the command is launched.

The recommended convention is to launch all experiments from the project root:

```bash
python -m experiments.train_agent
```

The Hydra-based scripts use `hydra.utils.to_absolute_path` for input and output paths. This makes path handling more robust if Hydra's working-directory behavior is changed later.

The plotting script is not Hydra-based, so its paths are interpreted directly by Python relative to the current working directory.

## Reproducibility

We ran the training and $\tau$-mixing estimation procecedures described above for the environments `CartPole-v1`, `FrozenLake-v1`, and `LunarLander-v3`. We used the default hyperparameters reported in the paper that are also set as defaults in the config files in this package. 
We stored all the data in a `./data` directory during this process, corresponding to:
  1. The replay buffer of all three training runs.
  2. The minibatches logged during training.
  3. The trained models saved after completion of training.
  4. The estimated $\tau$-mixing coefficients for the minibatches.
  5. The estimated $\tau$-mixing coefficients for trajectories generated using the trained models from 3.

Since this directory is very large (~2GB), we add it to an anonymous google drive folder that can be found at:

```text
https://drive.google.com/drive/folders/17ViOgp4FbvKjIX8eHlze5-vjO46JhpPC?usp=drive_link
```
The figures in the paper can be reproduced simply by using the `plot_tau_estimates.py` script in this package as follows (using cartpole as an example):

### Docker Reproducibility

This repository includes a Dockerfile for reproducing the experiments in a clean environment.

#### Build the Docker image

From the project root, run:

```bash
docker build -t tau-mixing-dqn .
```

#### Start an interactive Docker container

```bash
docker run --rm -it \
  -v "$(pwd)/data:/workspace/data" \
  -v "$(pwd)/figures:/workspace/figures" \
  -v "$(pwd)/models:/workspace/models" \
  -v "$(pwd)/results:/workspace/results" \
  tau-mixing-dqn
```

All commands in the rest of this README can then be run inside the container. Below we provide simple commands to reproduce the experiments within the Docker container.

#### Experiments pipeline

##### Reproducing experiments from the stored data

All experiments can be reproduced within this Docker container. The experiments for estimating the mixing coefficients require extensive runtime. To this end, we have included a link to download the data stored from our experiments. After downloading the data, one can simply run
```bash
bash reproduce_figures.sh
```
which will reproduce the figures.

##### Reproducing all experiments from scratch

To simplify reproducing the experiments, we add scripts which can be used to recreate the entire experiment pipeline for a given environment. This includes:
1. Training an agent and and logging the minibatches.
2. Estimating the mixing coefficients on the minibatch.
3. Estimating the mixing coefficients in the trajectory by generating rollouts using the fixed, trained policy from step 1.
4. Plot minibatch mixing coefficients.
5. Plot trajectory mixing coefficients.

This can be achieved for each environment as follows:

1. For `CartPole-v1` run:

```bash
bash reproduce_cartpole.sh
```

1. For `FrozenLake-v1` run:

```bash
bash reproduce_frozenlake.sh
```

1. For `LunarLander-v3` run:

```bash
bash reproduce_lunarlander.sh
```
